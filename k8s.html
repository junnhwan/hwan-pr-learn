Kubernetes 语义速查

写诊断逻辑时最容易踩的坑，以及对应的真实 PR。

概念该看什么常见误判相关 PR
conditions 按 type 查，不按下标取；关注 status 与 reason 只看 Conditions[0]（顺序不保证） #1737 · #1740
status 新鲜度 metadata.generation vs status.observedGeneration 把"正在收敛"当成故障 #1743
终态 vs 计数 Job 看 Complete / SuccessCriteriaMet；RS 看 ReplicaFailure status.failed > 0 就报失败 #1725 · #1750
命名空间作用域 用对象自身的 namespace 查询，而不是用户传入的 全局分析时 namespace 为空 #1747 · #1753
Event 关联 involvedObject 的 kind + name（最好 uid），且 Event 与对象同 namespace 同名不同 Kind 串味 #1753
引用扫描 containers + initContainers + volumes + projected sources 漏掉一类挂载点 → 误报"未使用" #1722 · #1741
多态引用 看到 Kind 字段就要分支（RoleRef / paramRef / deviceClassName） 只处理最熟悉的那一种 #1755 · #1768
有状态序号 spec.ordinals.start 决定起始序号，Pod 名 = $(name)-$(ordinal) 假设从 0 开始 #1759
列举分页 S3 IsTruncated/ContinuationToken；k8s List continue 只取第一页 #1760
